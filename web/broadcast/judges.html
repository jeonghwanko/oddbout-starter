Try it in 10 minutes

Each step shows what you should see.

What you need

  • Any Google account
  • The PayPal Sandbox buyer login from our Devpost testing instructions
  • A short MP4, or our sample clip (6 s, 31 KB)

Steps and expected results

  1. Sign in with Google.Your DON shows 0
  2. Add DON → Starter, USD 10. Approve with the Sandbox buyer.“1,000 DON added”
  3. Choose 1 hour for 300 DON.A ticket with four fighters
  4. Add your promotion: the MP4 and a promo URL, then Save Promotion.An AI-written sponsor introduction
  5. Add to Calendar → On-Air Agent → tick the check → Start.“Agent running”
  6. Wait for the first cup, about 5 minutes, then open Watch broadcast.Your promo break and a replay of the verified bout
  7. Press End broadcast and confirm. The current cup finishes.“Finished”
  8. Press Check settlement.Settlement shows “Matched”
  9. Tick the approval for the creator fees and press Pay with PayPal.“Paid · PayPal batch … · every recipient SUCCESS”

One graphical runner serves this demo. If Start says another broadcast is using the host, your ticket is saved: try again in a few minutes. Ending after the first cup keeps the runner free for the next judge.

Where PayPal does the work

Orders v2 · Checkout
Create, buyer approval, server capture. A COMPLETED capture is checked against the payee, amount, currency and the account's own top-up before any DON is credited.
Webhooks
Signatures are verified with PayPal's verification API. Capture events use the same credit function as the synchronous capture, and a capture ID credits once. Refund and reversal events are stored once per event ID and freeze spending.
Official PayPal MCP server
@paypal/mcp, started with only the read tools get_order, list_transactions and get_refund, and refused if it offers more. The server compares each top-up that funded the ticket with get_order.
Payouts
Creator appearance fees, sent only after the owner approves. A retry reuses the same batch ID, so it can never create a second batch. A refund or reversal freezes payment.

Where AI does the work

On-Air Agent
A model reads the ticket's lineup and remaining time and proposes the next move: host a cup, wait or stop. The server validates each proposal and hosts cups only through ODDBOUT's MCP tool host_cup, with a grant scoped to that one broadcast. It cannot pay or change prices, limits or payouts. On Nov 4 the model was Sol 6.1.
Sponsor introduction
Written from the promo URL's hostname only, labeled as a paid sponsor break, with no product claims. The owner reviews it before pressing Start.
Settlement auditor
Explains the PayPal MCP check to the owner and may call the same read-only tools to look into a mismatch. The server's comparison decides the result, never the model.
Bounded by design
Model calls are capped per broadcast and per day. An unusable AI answer shows Retry Agent, which continues the same ticket with no extra charge.

What this demo does not claim

  • PayPal Sandbox only. No live payments or real customers.
  • Creator payouts always wait for a person to approve them.
  • One graphical runner serves the demo, so one broadcast runs at a time.
  • The watch page replays verified bouts on the web. It is not a Twitch stream.
  • Our Nov 4 run was ended after about 20 minutes. A full hour, including the second sponsor break, is not yet verified on the hosted demo.
  • Live Twitch or YouTube output and 24-hour runs are planned work and not verified.
