# X에 올리기 (`fighter:social`)

완성한 선수를 X(트위터)에 올릴 파일로 꺼낸다. 패키지와 프로필 세트를 **읽기만** 하고 새 폴더에 쓴다.

- 생성은 0회다. 생성 쿼터를 쓰지 않는다.
- 제출한 패키지는 건드리지 않는다.
- 게시는 사용자가 자기 X 계정에서 직접 한다. 킷은 X에 로그인하지 않고 게시하지도 않는다.

## 명령

```sh
npm run fighter:social -- --package <fighter.json이 있는 폴더> --profile-set <profile-set.json이 있는 폴더> --out output/<이름>-x
```

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `--size 720\|1024` | 720 | 캔버스 크기. 1024는 X 영상 높이 한도(1024)에 맞춘 최대 정사각형이다 |
| `--aspect 1:1\|16:9` | 1:1 | 16:9는 1280×720 |
| `--bg light\|dark\|#rrggbb` | light | 배경색. 투명 GIF는 X의 라이트·다크 테마 중 한쪽에서 가장자리가 보이므로 쓰지 않는다 |
| `--clips combo,slam` | 전부 | 따로 내보낼 모션 |
| `--no-endcard` | 켜짐 | ODDBOUT 엔드카드와 구석 표시를 끈다 |
| `--no-gif` | 켜짐 | MP4만 쓴다 |
| `--silent-audio` | 꺼짐 | 무음 AAC 트랙을 넣는다. 오디오 트랙을 요구하는 업로더용이다 |
| `--add-clip <mp4>` | 없음 | 다른 곳에서 만든 완성 클립(요청한 Grok 표정 클립)을 같은 캔버스와 표시로 가져온다. 여러 번 줄 수 있다 |

작업 공간 MCP에서는 `export_social_media`가 같은 일을 한다. 출력은 `output/` 아래의 새 폴더만 받는다.

## 출력

| 경로 | 내용 |
| --- | --- |
| `showcase.mp4` | 전투 대기 → 콤보 → 강타 → (스킬·승리) → 엔드카드(정면 그림, 이름, 표정, oddbout.com) |
| `clips/<모션>.mp4`, `.gif` | 모션별 루프. 3–6초가 되도록 반복한다. 한 번만 하는 동작은 두 번 이상 재생한다 |
| `reactions/<표정>.png` | 여섯 표정의 512px 투명 PNG. 스티커를 받는 앱에 쓴다 |
| `reactions/<표정>.mp4`, `.gif` | 표정별 1.2–2.4초 리액션 루프. 답글용으로 GIF는 3MB 안팎을 목표로 한다 |
| `post-set/1.png`…`4.png` | 이미지 네 장짜리 게시물: 정면 + 표정 셋(시트가 없으면 공격 장면) |
| `POST.md` | 캡션 링크(`x.com/intent/post`), 해시태그, 링크는 첫 답글에 넣으라는 안내 |
| `social.json` | 파일마다 크기·해시·길이와 X 한도 검사 결과 |

표정은 프로필 세트의 표정 시트(`default`, `hit`, `smug`, `danger`, `sideeye`, `ko`)에서 자른다. 그림을 새로 그리지 않고 카메라만 움직이는 프리셋을 쓴다.

| 표정 | 프리셋 |
| --- | --- |
| default | 숨쉬기 |
| hit | 흔들림 + 번쩍임 |
| smug | 통통 튀기 |
| danger | 떨림 |
| sideeye | 느린 줌인 |
| ko | 어지러운 흔들림 |

시트가 없는 세트는 정면 그림의 얼굴 사각형을 여섯 프리셋으로 움직인다. 아레나도 시트가 없으면 같은 얼굴을 쓴다.

모션 배치 규칙:
- 각 프레임은 자기 원점(`origins`)을 공통 지면선의 같은 자리에 둔다. bbox를 가운데 맞추지 않으므로 발이 떨리지 않는다.
- `pixelScale`로 줄인 시트도 게임 크기 그대로 보인다.
- 쇼케이스는 모든 클립이 한 무대(같은 배율, 같은 자리)를 쓴다.

## X 한도

X가 공개한 업로드 규칙(docs.x.com, 2026-11-12 확인)으로 각 파일을 검사한다.

| 미디어 | 한도 |
| --- | --- |
| GIF | 15MB, 1280×1080, 350프레임, 가로×세로×프레임 3억 이하. 넘으면 프레임 수 → 크기 순으로 줄인다 |
| 영상 | H.264 High, yuv420p, 짝수 크기, 1280×1024 이하 |
| 이미지 | 5MB, 한 게시물에 4장 |

`social.json`의 `xLimitsChecked`는 킷이 직접 한 검사다. X가 받았는지는 실제 업로드로만 알 수 있다.

## Grok 표정 클립 (선택, 요청할 때만)

프리셋은 생성이 필요 없다. 표정이 직접 움직이는 클립을 원할 때만 사용자 본인의 Grok 계정으로 만든다.

1. 준비만 한다(생성 없음).
   ```sh
   npm run fighter:social -- grok-face --profile-set <세트> --face sideeye --out output/<이름>-grok-sideeye
   ```
   정사각형 스틸, 프롬프트, 실행할 `npm run sprite -- video` 명령을 돌려준다. 스틸을 첫 프레임과 마지막 프레임(`--last-frame`)에 모두 써서 루프가 된다. MCP 도구는 `prepare_grok_face_clip`이다.
2. 사용자가 그 클립을 요청했을 때만 명령을 실행한다. 사용자의 Grok 로그인과 쿼터를 쓴다. 결과를 알 수 없으면 리포트로 `npm run sprite -- video-resume`을 써서 복구하고, 다시 보내지 않는다.
3. 완성된 클립을 `--add-clip <clip.mp4>`로 새 출력 폴더에 가져온다.

## 올리는 순서 (POST.md)

1. **소개:** `post-set` 네 장과 캡션을 올린다. 링크(`https://oddbout.com/?ref=x`)는 본문이 아니라 첫 답글에 넣는다.
2. **움직임:** `showcase.mp4` 하나를 올린다.
3. **답글:** 다른 글에 표정 GIF로 답한다. X에는 사용자 스티커나 커스텀 이모지가 없으므로 이게 "내 캐릭터 이모지"다.

자기 캐릭터만 올린다. 다른 사람의 캐릭터를 자기 것처럼 올리지 않는다.
