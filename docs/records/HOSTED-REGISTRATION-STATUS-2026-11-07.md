# 호스팅 제작 자동 등록과 상태 표시 — 2026-11-07

사용자 요청: 호스팅 모션의 추가 승인을 없애 등록까지 진행하고, 출전은 사이트에서 하도록 한다.
GPT 웹에서 진행 중인지·완료인지·누가 무엇을 해야 하는지 구분할 수 있게 한다.

- 외형 선택 이후 `motions` 성공은 같은 DB 트랜잭션에서 `submitting`으로 넘어간다.
  기존 소유권·계정 한도와 패키지 검사 경로를 사용하며 출전을 실행하지 않는다.
- 등록 전환이 거절되면 완성된 preview를 보존하고 `needs_review`와 원인을 남긴다.
  새 생성이나 무제한 재시도를 하지 않는다.
- 기존 `motion_ready` 행을 일괄 변경하지 않는다. 에이전트가 기존 hosted 등록 도구로 이어간다.
  등록 응답이 유실되어 다시 호출해도 이미 submitting/submitted라면 현재 상태를 반환한다.
- 전체 응답·짧은 대기 응답·최근 목록에 `statusSummary`를 제공한다. 등록 응답의
  `stage=registered`만 완료다. 100%는 현재 단계 진행률이며 전체 완료율이 아니다.
- GPT 카드에 상태, 필요한 행동, 대기 순서/중단 사유, 작업 갱신·조회 시각, 사이트 링크를 표시한다.
  실시간 자동 알림이라고 약속하지 않는다. 후보 비교 UI와 URL 제한은 유지한다.

## 확인과 반영 범위

로컬 DB 테스트(PGlite)에서 자동 등록 전환, 프로필 누락 시 결과 보존, 소유자/프로필 유지,
중복 완료 호출 거절을 확인했다. 상태 카드 DOM과 단계별 완료 판단, 기존 대기 작업의 수정·등록,
서버 제출과 프로필 연결 회귀를 검사했다. 실제 GPT 웹에 배포한 UI 시험이나 새 생성 시험은 하지 않았다.

반영은 `AGENTS.md`와 `docs/CREATOR-HOSTING.md`의 배포 경로를 따른다. 통과한 main 변경을 기준으로
DB 마이그레이션 `20261107112111_hosted_auto_registration.sql`과 hosted MCP 변경을 함께 반영해야 한다.
MCP 모듈을 포함하는 Render/Edge 배포 및 이후 제작 키트·스킬 배포 범위를 확인한다.
이 문서 작성만으로 배포·캐릭터 등록·출전이 수행된 것은 아니다.
