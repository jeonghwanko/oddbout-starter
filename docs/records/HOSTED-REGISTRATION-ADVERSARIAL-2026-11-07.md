테스트가 loopback의 임시 포트·새 클러스터를 만들고 종료·삭제한다. 일반 `npm test`와 별도로 실행하는 선택 검사다.

| P2 | 제출 단계에서 3회 재시도하거나 완료 보고를 잃으면 다음 claim이 `failed`로 종료했다. 이미 접수한 패키지까지 운영자 재개가 막히고 폴더 종료 대상이 됐다 | 자동 재시도는 기존 3회에서 멈추되 `needs_review`로 보존. 실제 API로 임대를 소진하고, 종료 목록에서 제외되는지·일반 계정의 재개가 거절되는지·운영자 재개가 등록 단계만 돌려주는지·기존 제출 ID로 완료되는지 확인 |
| P2 | 모션은 완성됐지만 제출을 아직 맡지 않은 커뮤니티 PC가 하루 이상 끊기면, ‘이번 단계 미실행’으로 판단해 `failed` 처리했다 | 제출 단계는 임대 이력이 없어도 `submitting-host-lost` 운영자 확인으로 보존. 다른 PC로 넘기지 않으며 미완성 생성 단계의 기존 처리도 유지 |

현재 절차 문서에 남아 있던 ‘동작 승인 후 등록’·‘맡기기여도 마지막 등록은 사용자 응답’ 안내도 자동 등록과 사이트 출전에
맞췄다. 호스트 운영 문서에는 위 두 복구 예외를 반영했다.

배포되지 않은 마이그레이션에 현재 claim·host-lost 함수를 재정의했다. 함수 권한을 유지하는
[`CREATE OR REPLACE FUNCTION`](https://www.postgresql.org/docs/current/sql-createfunction.html)과 기존 `security invoker`를 사용한다.
새 테이블·권한 확대·다른 PC 배정·생성 호출은 없다.

검증 결과: 등록·호스트·복구 35개, 상태 카드·마이그레이션 규칙·safeupdate 21개, 실제 PostgreSQL 동시성 3개로
총 59개가 통과했다. `npm run typecheck`와 `git diff --check`도 통과했다. DB/API는 로컬 fixture이며 접수 검사는
저장소 메타데이터를 사용했다. 운영 배포, 실제 GPT 웹 연동, 새 캐릭터 생성은 하지 않았다.
